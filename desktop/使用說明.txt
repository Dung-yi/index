每日工作日誌：電腦主機版（單一帳號）

一、在這台電腦使用
1. 將整個資料夾放在固定位置；不要只複製 index.html。
2. 第一次先雙擊「建立桌面捷徑.cmd」，之後點桌面的「每日工作日誌」即可啟動。
   也可直接雙擊「啟動.cmd」。啟動中心會啟動主機並自動打開瀏覽器。
   首次啟動會另開視窗，要求建立 Email 及至少 12 字元的新密碼。
   密碼在啟動視窗輸入時不會顯示。這是本機版帳號，與原網站帳號分開。
3. 用瀏覽器開啟 http://127.0.0.1:8765 並登入。
4. 關閉「啟動中心」後主機仍會在背景運行；按「停止主機」才會結束服務。
   關機、睡眠或網路中斷時，手機仍無法連線。
   如果移到其他電腦，請安裝 Python 3.11 或更新版本（包含 Python Launcher）。
   此電腦也可使用已安裝的 Codex Python，不需額外安裝套件。

二、把原網站資料搬過來
先在啟動中心按「停止主機」，再雙擊「搬移原網站資料.cmd」。
在你自己的電腦視窗輸入原網站的 Email 及密碼，不必把密碼傳給任何人。
會先下載該登入帳號能讀取的資料，再匯入本機資料庫，保留日期、進度及流程。
匯入前會備份；重複搬移相同來源 ID 會跳過，不會刪除雲端紀錄。
再次搬移不會更新已匯入的紀錄，請完成搬移後選定一邊作為主要使用版本。
搬移需要可連上 Supabase 的網路；本機版平常操作不需要 Supabase 或 CDN。
雲端資料與本機資料不會自動同步。搬移完成後重新啟動本機版並核對筆數與內容。
如原帳號需要多因素驗證，這個搬移工具不支援；請改由管理者提供 JSON 匯出檔。

三、讓外面的 iPhone 連線（尚未設定）
這是公司電腦，請先讓公司資訊人員確認可使用的遠端方式及資料存放政策。
建議由資訊人員安裝 Tailscale，電腦與 iPhone 加入同一個核准的私人網路。
iPhone 從 App Store 安裝 Tailscale，依畫面允許 VPN 設定並登入。
不要把這個服務直接開放到公開網路，也不要使用 Tailscale Funnel。
電腦端由資訊人員確認目前指令說明後設定：
  tailscale serve --help
  tailscale serve --bg http://127.0.0.1:8765
  tailscale serve status
依官方提示啟用所需的 HTTPS 功能；將顯示的 https://…ts.net 網址存到手機。
私人網路的存取規則應只允許你的裝置／帳號連到這台主機的 HTTPS 服務。
外出時：電腦開著、本機版啟動、兩台設備 Tailscale 連線，iPhone 用 Safari 開啟該網址。
第一次登入本機版需要本機版密碼，原網站密碼不會自動通用。
請以 iPhone 關閉 Wi-Fi、使用行動網路，驗證登入、修改及重新整理後資料仍存在。
如公司不允許安裝，請改由資訊人員提供核准的 VPN／內部主機方案。
遠端模式需要主機和手機都有網路；電腦單機操作才可完全離線。

四、備份與還原
資料存放於 data/diary.sqlite3。每次啟動會備份到 backups 資料夾。
首頁的「下載資料備份」可下載 JSON，只包含工作紀錄，不包含登入密碼。
定期將 backups 複製到公司核准的另一個儲存位置，避免主機故障時一起遺失。
SQLite 備份含帳號密碼雜湊及工作紀錄，JSON 也含工作資料，請妥善保管。
完整還原：先按「停止主機」，保留目前 data 資料夾副本；再將選定的 SQLite 備份複製為
data/diary.sqlite3，舊的 diary.sqlite3-wal、diary.sqlite3-shm 需一併移到副本，不可混用。
JSON 匯入可在此資料夾的終端機執行 Python server.py --import-file 備份檔路徑。
忘記本機密碼時請找管理者協助，不要刪除整個 data 資料夾。

五、目前限制
單一擁有者帳號。多人同時編輯同一筆紀錄時，最後儲存的欄位為準。
不包含開機自動啟動或防睡眠設定，可由資訊人員依公司規範設定。
尚未在你的 iPhone 完成遠端測試；須待遠端軟體核准、登入與連線設定後驗證。

六、檢查更新
1. 桌面捷徑會開啟「啟動中心」，按「檢查更新」。沒有新版時不會重裝。
2. 有新版會先顯示版本並詢問是否安裝，請先儲存電腦和手機上正在編輯的內容。
3. 所有檔案下載並驗證成功後，才會暫停主機、備份、替換程式及重新開啟網頁。
   完成後關閉啟動中心，再按桌面捷徑開啟新版啟動中心。
4. 更新只會替換指定的程式檔，不會覆蓋 data、backups 或你的工作紀錄。
   更新失敗會嘗試復原原程式；若更新途中斷電，下次啟動會先復原，再請你重開。
5. 公司網路擋住 GitHub 時，按「從更新檔安裝」，選取我提供的新版 ZIP 即可。
   只安裝可信來源的更新檔；檔案雜湊可偵測損壞，不代表第三方 ZIP 可被信任。
6. 更新來源是你自己的 Dung-yi/index 儲存庫 desktop 分支，與線上版 main 分開。
   我修改並發布新版後，此按鈕才能下載新版，不會自動取得尚未發布的聊天內容。
7. 從舊版首次換到啟動中心時，請手動關閉舊版的黑色啟動視窗後，再用新捷徑。
8. 桌面捷徑連到目前資料夾。不要移動資料夾；移動後需重新建立捷徑。
9. 主機啟動失敗時，可查看 data/host.log；請不要公開含個資的紀錄檔。
